# Internal build contract

Monorepo: Next.js web, NestJS API/worker, Expo Android, shared TypeScript domain and PostgreSQL database.

Database exports `Database` class (constructor accepts optional Pool or connection string); `MemoryDatabase` test adapter; `Context` `{tenantId,userId,role,organizationId?,facilityIds?,assignedDriverId?,correlationId?}`. Roles: owner, operations, driver, customer_admin, receiver, finance, customer_finance, auditor, control_room, warehouse, sustainability, platform_admin.

`Database.transaction<T>(context, callback: (tx: Transaction)=>Promise<T>):Promise<T>`. Transaction: `get<T extends Entity>(kind,id):Promise<T|undefined>`, `list<T extends Entity>(kind):Promise<T[]>`, `put<T extends Entity>(kind,entity):Promise<void>`, `delete(kind,id):Promise<void>`, `audit(action,target,details?):Promise<void>`, `emit(type,aggregateId,payload):Promise<void>`. Entity `{id:string,[key:string]:unknown}`. JSON entity repository backed by forced PostgreSQL RLS, row locks and tenant scoped transaction. Auth SQL tables separate; no unauthenticated tenant selection. This is an initial modular implementation; not a capacity claim.

Domain exports types and `WorkflowService` constructor(database:DatabasePort, options?:{otpSecret?:string,deliverOtp?:(contact:string,code:string)=>Promise<void>,now?:()=>Date})`. Public `execute(ctx,action,input)` and `query(ctx,resource,id?)` can be exposed by API. `execute` actions: createOrganization, createFacility, createPolicy, grantReceiver, revokeGrant, createConsignment, createTrip, recordEvent, saveDraft, issueChallenge, acceptPod, correctPod, recordEvidence, markEvidenceScanned, evaluateBilling, recordGrn, createInvoice, submitInvoice, respondInvoice, allocateReceipt, createDispute, createComplianceTask, resolveComplianceTask, importPreview, importCommit. query resources: dashboard, organizations, facilities, policies, grants, consignments, trips, pods, billing, invoices, disputes, compliance, audit, outbox, evidence. IDs UUIDs except deterministic fixture IDs. Typed input schemas Zod validation, errors HTTP compatible `{status,code,message}`. No raw OTP returned outside explicit development adapter. API maps domain operations to REST; additionally POST /v1/actions/:action and GET /v1/resources/:resource provide generic access. Web can use those stable generic paths with Bearer JWT obtained from POST /v1/auth/login `{email,password}`. GET /v1/auth/me current context. Login returns `{accessToken,user:{id,name,email,role,tenantId,organizationId?}}`. No production demo role switching.
